# 文件流程（3.2）

主 Agent 只准备输入、派发任务和交付结果。将命令中的路径换成实际绝对路径，python 换成宿主可用的 Python 3.8+。

## 1. 统一提取入口

在技能包之外创建本次工作目录 WORK。使用用户可下载且不会自动清理的目录。主 Agent 不按摘要重建原文。

所有文件都先调用同一个入口；长粘贴原样保存为 TXT 后也用此命令：

```text
python "<SKILL>/scripts/extract_file.py" --input "<SOURCE>" --output "<WORK>/document.json"
```

只按返回的 action 行动：

| action | 主 Agent 操作 |
| --- | --- |
| ready | 已生成 document_path；按长度和结构选择短文或文件校对 |
| install_dependency | 仅为返回的 python 解释器安装 requirement，使用内网包源或离线包；然后执行 retry_command |
| host_extract | 按 instruction 使用宿主现成读取工具，把完整原文写入 host_output_path，然后执行 resume_command |
| blocked | 修正实际来源、输出或宿主结果问题；没有有效 document.json 不启动校对 |

同一依赖安装后只重试一次；仍失败或无法安装时执行 fallback_command，转交宿主工具。脚本自身不安装、不联网。不要因一份附件去搭建完整转换环境，也不要在内置提取与宿主回退之间循环。

宿主提取必须由工具写入文件，不由主 Agent 凭摘要复写。默认接收 UTF-8 文本，保留段落、工作表及幻灯片分隔；有带准确位置的结构化结果时也可接收。恢复时可用 --scope 记录实际返回范围，不能声明未读取部分。宿主也失败时说明原因、请求可读取的转换件。

TXT/TEXT/MD/Markdown 原样读取；DOCX 使用已有标准库适配器。XLSX、PPTX 优先使用可用解析库，库不可用或失败时由现有标准库适配器接手。旧 XLS 可选 xlrd；DOC/PPT 和未识别的 WPS 原生格式交给宿主。不是对所有 Office 特性或 WPS 版本的完整兼容承诺。详细范围和维护约定见 [提取说明](extraction.md)，正常任务不必提前加载。

提取后约 500 字以内且结构简单的材料返回短文分支；suggested_delivery 只是长度建议，复杂表格或多个片段仍由主 Agent 按实际结构判断。其余进入下列队列。

## 2. 取任务、派发、等待

COORDINATOR 使用本次主 Agent 会话的稳定标识；宿主没有时创建一个随机 ID 并在本会话沿用。它是调度属主，不是检查员隔离证据。

```text
python "<SKILL>/scripts/tasks.py" step --work "<WORK>" --coordinator "<COORDINATOR>" --concurrency <N>
```

只按 action 执行：dispatch 原样派发 tasks 中的 prompt；wait 等已有任务完成；repair 读 [异常恢复](recovery.md)；deliver 交付 report_path。

不让主 Agent 转述正文、设计子任务指令、合并候选或写报告。每个派发 prompt 已含 open 命令；open --brief 只给检查员角色指令和所需文件路径。返回 stop_no_work 时该执行立即结束。

每有一个子任务完成就再 step，脚本填补空闲槽位。使用宿主任务句柄；宿主已关联任务时，不重复抄写 ID 映射。只有无法关联时才保留最小对应关系，必要时用工具落盘到 WORK/host-tasks.json，不放正文或结果。不要提前读取另一初检路的结果或复用已接触另一检查路结果的上下文。

一次派发所有已返回任务，不逐个派发后等待。优先使用宿主“任意一个完成即返回”的等待工具或完成通知，收到就 step，不等整轮收齐。禁止自行添加 45/120/180 秒这样的固定 sleep。没有完成通知时运行 wait 动作返回的 wait_command；最多等待 60 秒，看到可推进状态提前返回。返回 step 就立即 step，超时不表示任务失败。

子代理成功只回“任务 ID + submitted”，失败只回“任务 ID + blocked + 简短类别”，不回正文、候选或总结。主 Agent 不读取 responses 明细，脚本负责接收；字段修正由原检查员完成。

主 Agent 的固定循环：`step → dispatch 时派发全部返回任务 → 等待任意完成 → step`。没有宿主通知时，运行 `wait_command`；返回 `wait` 就重复同一等待命令，返回 `step` 才调用 step。超时返回 wait 是正常状态，不需要查源码或修复。启动记录变化不会单独唤醒等待；完成、失败或可推进状态会提前返回。不要预设必须循环多少轮。

### 并发和分块

容量未知时首次直接省略 --concurrency，采用默认 4；不要求主 Agent 先探测。后续继续省略，沿用工作区值。部署方提供了明确容量时才显式设置。N 受宿主槽位和内网推理服务能力约束；脚本兼容大于 4 的并发，未指定时初始默认 4。首次按实际可用数量配置，之后省略沿用原值；运行中可调整，并不会中断已在执行的任务。降低上限时等待已有任务释放槽位。

优先使用部署方已验证的并发值或宿主明确提供的容量；启动 4 个成功不能证明支持 16 个。本地脚本无法探测宿主模型服务容量。容量未知时先用默认值并及时补位；部署方可以相同材料实测 8/16，比较吞吐和失败率后固定配置，不承诺线性提速。

分块保持目标 1600 字、上限 2000 字的现有默认值。相邻上下文只助理解，不能重复计入本批发现。并发变多不改变每批质量要求；不要同时修改分块大小和并发来宣称提速有效。部署时用相同材料分别比较 4/8/12 等可用档位的整篇耗时、失败率和结果质量，档位不是承诺的最优值。

## 3. 自动收尾和交付

提交有效结果后，submit 接收结果并自动推进不需要模型的步骤，不预留新子任务、不变更主 Agent 属主。最终复核收齐时，同一次提交生成并校验“校对报告.html”；零候选也生成完整报告。

主 Agent 继续 step，拿到 action=deliver 后给用户文件或宿主下载链接。报告保持原文、明确意见与疑点分开，离线可读并可打印；不生成网页服务。只有 JSON 或子任务成功消息不算完成交付。

异常时再读 [异常恢复](recovery.md)，无需正常任务提前加载锁、票据、接管细节。旧 next --compact 接口仍保留供诊断。status 只观察状态，不证明报告文件当前有效，交付以 step 的实际校验为准。
