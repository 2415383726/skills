# 校对规则维护

仅供维护者读取，正常校对不加载本文件或测评答案。

## 稳定的流水线与可迭代的判断

流水线只认识原文单元、候选、复核决定和交付状态。语言判断分别由 rules.md、formats/proofread.md、formats/consistency.md、formats/review.md 指导。

- 新增词语判据、正确表达反例、技术语境例外：编辑 rules.md。优先归入已有 rule_id，不为每个词新建编号。
- 调整初检阅读策略或复核判断方法：修改对应角色说明，保持 JSON 字段契约不变。
- 确需新增同类规则编号：在 rule-catalog.json 登记，并在 rules.md 给出适用语境、排除条件和最小修改例子；不用改调度、合并或报告代码。requires_necessity=true 表示接受该规则候选时必须给出必要性依据。代码仍按实际改动要求补删字等提供依据，不能靠换编号绕过。
- 尽量使用现有 T-/W-/P- 编号族，使现有测评分项能够正确归类；新增范围之外的编号族需要另行设计评价指标，不能默默计作已有质量提升。

规则、规则目录和三个角色格式一起参与版本指纹。更新后为新材料创建新工作目录；不在运行中的任务里混用新旧判断规则。这不需要改流水线代码。

增加政策核验、金额计算、跨文件证据检索等新能力涉及新输入或新结果契约，需要单独评估，不能仅通过扩大 rules.md 宣称支持。

## 用结果决定是否保留规则

每次修改使用人工审定的真实材料和未写进规则的留出样本，比较新增正确发现、误报、正确表达误改及复核误删。保留能够说明规则边界的少量例子，不把每个历史案例都堆进提示词。

同一模型多路检查可能同错。格式通过、填写依据、并发增加都不能证明判断更准。使用 evaluation.md 中的分阶段测评；内置未审定开发样例仅作回归，不作为准确率宣传。
