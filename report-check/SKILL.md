# 报表智能复核

报送前的数字把关。上游 validate-data 的经验是：复核要在分享**之前**做，而且机械检查和语义判断要分开——机器管"算得对不对"，人管"算得该不该"。本技能照此分工：脚本跑确定性检查，模型做语义复核，都不缺。

## 复核流程

1. **明确复核范围**：这是给谁看的报表、有无口径说明、有无配套的底表或历史报表。底表给进来可以核"报表数 vs 底表数"。
2. **机械检查**（脚本，保证覆盖每一个数值列）：
   ```bash
   python "<SKILL>/scripts/check.py" 报表.xlsx --out 复核清单.md
   ```
   检查项：合计行与分组数据之和、负值、0%/100% 可疑比率、超中位数 3 倍的跳变、空值、形似数值但无法解析的单元格。表头不在第一行用 `--header`。
3. **语义复核**：按 [交付前复核清单](references/checklist.md) 逐项过——口径定义、同比环比基期、跨表一致性、平均数的加权、图表是否歪曲数值。脚本查不了这些，但它们恰恰是报送后最容易被追问的。
4. **汇总红黄绿清单**：格式见 [复核清单格式](references/output-format.md)。红色＝确定性不一致（必须核实或更正后才能报送）；黄色＝可疑（逐项核对）；绿＝机械检查通过（语义项仍需人工确认）。
5. **建议更正值**：能算出的给出复核公式和建议值，标注"建议"，**不回写原表**——改不改由用户定。

## 底线

- 只读不写：原文件一律不修改、不覆盖；
- 每条问题给定位（工作表、行、列）和复核依据（公式或对照关系）；
- 查不了的明确说查不了：无底表时注明"未做报表数与底表的核对"；
- 允许零问题，不为凑数把黄色项说成红色项。

## 边界

- 从数据里算指标、写分析 → 数据分析技能；
- 分析文字材料的内容审读（结论有无支撑、逻辑是否自洽）→ 材料审稿技能；
- 数据导入系统前的字段级质量体检（身份证、日期格式、枚举值）→ 台账体检技能。
