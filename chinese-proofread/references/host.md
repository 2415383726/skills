# 宿主执行契约

仅部署、宿主能力不明确或调度失败时读取。规则不绑定某个产品的工具名称；脚本不调用模型、不验证模型是否在内网，该边界由部署方保证。

| 能力 | 所需行为 |
| --- | --- |
| 模型 | 使用部署方指定的内网模型，不为完成任务自动改用外部服务 |
| 新上下文 | 初检 A/B 与复核不继承其他检查员的历史；有历史继承开关时关闭，不只创建不同任务 ID |
| 本地命令 | 主 Agent 与子代理使用同一可用 Python 3.8+；按返回的 POSIX sh/PowerShell 类型执行命令 |
| 文件系统 | 所有执行者可读同一输入及技能目录、写同一 WORK；WORK 在技能目录之外且可持久交付 |
| 派发 | 将 tasks[].prompt 原样给新上下文，先派发全部返回任务再等待，保留宿主句柄与任务的对应关系 |
| 容量 | 默认 8 个子代理并行；已知宿主剩余槽位或服务上限更低时调低，总容量含主 Agent 时扣除主 Agent。容量未知仍使用 8 |
| 等待 | 宿主有自动完成通知时，派发后交还控制权，一条新通知就 step，同次已有多条才合并，不等凑批，无需 wait_command。无通知时单次执行 wait_command 并处理 JSON，不自建后台循环。超时不是失败 |
| 结束 | submit 成功不等于用户已收到报告；主 Agent 取得 deliver 后交付实际文件 |

能力检查只使用宿主已提供的说明和工具状态，不靠盲目创建大量任务探测容量。没有共享文件系统或独立子代理能力时，严格模式不可执行；报告具体缺少的能力，不启动注定无法运行的队列。已运行任务的失败恢复见 recovery.md。

默认严格模式适用于短文及文件。轻量模式仅在用户明确选择、短文结构简单时使用：主 Agent 按 short-text.md 生成初检指引，逐句校对，再检查每个候选是否必要，交付注明未经独立复核。不用严格模式的完成标识、双路执行记录或准确率说明包装轻量结果。失败的严格任务不自动切换轻量模式。

部署验收使用同一份带已知错误的非敏感样例，核对提取范围、A/B 新上下文、候选复核、报告下载和中断恢复。Windows 7 / 麒麟 V10 尚无实机验证记录，不以本机机械测试通过替代目标环境验收。轻量与严格模式的效果比较按 evaluation.md 执行。

提供真实 context_id 时，脚本拒绝在同一工作目录内跨任务复用它，包括初检后复用该上下文做复核。无真实 ID 时保持 unavailable，不生成随机 ID 冒充隔离证据。任务指引和输入路径的限制是执行约定，不是共享文件系统的权限沙箱。

身份文件、宿主句柄持久化、成对通知去重见[宿主事件协议](host-events.md)。异步通知型宿主通过结束当前回合交还控制权等待，不需要原生“任意一个完成”工具。
