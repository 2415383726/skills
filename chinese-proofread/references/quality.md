# 校对规则维护

仅供维护者读取，正常校对不加载本文件或测评答案。

## 稳定的流水线与可迭代的判断

流水线只认识原文单元、候选、复核决定和交付状态。每个检查员只读脚本生成的本任务指引与输入，不自行寻找其他角色资料。

| 维护对象 | 唯一来源 |
| --- | --- |
| 所有角色的范围、等级和共同边界 | rules.md |
| 初检阅读顺序与候选职责 | roles/proofread.md |
| 候选裁决步骤 | roles/review.md |
| 名称差异判断步骤 | roles/consistency.md |
| 聊天交付格式 | roles/chat.md |
| 文字、标点、名称的判据与对照示例 | checks/text.md、checks/punctuation.md、checks/names.md |
| 各角色 JSON 字段契约 | formats 下对应角色文件 |
| 规则编号与 necessity 开关 | rule-catalog.json |

scripts/guidance.py 为任务生成单份指引。初检读文字和标点；名称检查只读名称；复核按候选编号族与实际改动选择判据，未知编号保留全部判据。新领域或编号族必须同时检查路由与测试，不能只登记编号却不给判断规则。规则不在多个角色文件里重复维护。

新增判据应说明成立条件、排除条件和最小修改；使用成对的正反例。角色步骤与 JSON 格式分开，避免模型同时学习别人的职责。初检的名称附记只采集原字，不承担名称比较；名称判断保留给独立任务。

所有角色、领域、格式文件以及指引组装代码参与规则指纹；更新后新建工作目录。任务指引另有内容指纹，篡改后不领取、不提交。文件共享权限不由本技能隔离：执行隔离依赖宿主新上下文、关闭历史继承与最小读文件范围。

增加政策核验、金额计算、跨文件证据检索等新能力涉及新输入或新结果契约，需要单独评估，不能仅通过扩大 rules.md 宣称支持。

## 用结果决定是否保留规则

每次修改使用人工审定的真实材料和未写进规则的留出样本，比较新增正确发现、误报、正确表达误改及复核误删。保留能够说明规则边界的少量例子，不把每个历史案例都堆进提示词。

同一模型多路检查可能同错。格式通过、填写依据、并发增加都不能证明判断更准。使用 evaluation.md 中的分阶段测评；内置未审定开发样例仅作回归，不作为准确率宣传。
