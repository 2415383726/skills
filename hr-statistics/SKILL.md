# 人力资源统计分析

人事数字直接进领导决策，所以上游 people-report 的两条纪律要守住：**口径先行、方法透明**。所有报告必须能回答"这个数怎么算的、截至哪天、含哪些人"。

## 流程

1. **明确问题与范围**：要哪种报告（结构月报/编制实有/退休预测/管理幅度）、台账范围（在编还是含聘用）、基准日。拿不准先问，口径错了全部白算。
2. **认识台账**：确认字段齐不齐——姓名/部门/学历/出生日期/性别/入职日期/状态。字段名不同（"出生年月"）用近似匹配，找不到的列列出来向用户要。
3. **统计计算**（脚本只读台账，输出汇总表）：
   ```bash
   python "<SKILL>/scripts/stats.py" count-by 台账.xlsx --col 部门
   python "<SKILL>/scripts/stats.py" pivot 台账.xlsx --rows 部门 --cols 学历
   python "<SKILL>/scripts/stats.py" ages 台账.xlsx --col 出生日期 --brackets 30,40,50 --asof 2026-09-13
   python "<SKILL>/scripts/stats.py" retire 台账.xlsx --col 出生日期 --gender 性别 --years 5
   ```
   表头不在第一行用 `--header`。全部命令和输出保留进报告，保证可复现。
4. **交付前校验**：分项之和＝总人数；与上期报告衔接（本期数±变动＝上期数则对得上）；异常（超编、年龄断层、到龄集中）单独列出。
5. **按模板出报告**：结构与口径见 [人员统计口径与报告边界](references/metrics.md)——领导摘要 → 关键指标（含趋势）→ 分项分析 → 异常提示 → 口径与方法。

## 硬边界

- **不排名、不评价、不决策**：不输出"人员优劣排名"，不产生任免调岗建议；客观结构数据可以给，管理判断归人工。
- **脱敏**：报告只有汇总数；姓名、证件号、薪酬等个人明细不进报告不落盘。
- **口径变更声明**：与上期比，台账范围或算法变了必须在报告中写明。
- 台账本身数据有问题的，先转台账体检技能处理，不硬算。

## 边界

- 导入前的数据质量检查 → 台账体检技能；
- 一般性数据问答和临时分析 → 数据分析技能；
- 干部个案、绩效、薪酬分析属高敏场景，本技能默认不处理。
