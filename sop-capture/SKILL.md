# SOP 流程沉淀

把"存在某个人脑子里"的流程变成组织资产。上游 process-doc 的三条经验是本技能的底色：**从乱糟糟的口述开始没关系**；**例外场景最有价值**（"一般这样办，但遇到……就得那样"）；**点名到具体人**（角色会变，今天的实情先记下来）。

## 流程

1. **收口述**：请用户像跟新同事交代工作那样讲一遍流程，想到哪说到哪，不用整理。已有的零散说明、制度节选、表单截图、系统操作记录一并拿来。
2. **访谈补齐**：对照 [访谈问题清单](references/interview.md) 逐项检查缺口，一次问 3 个以内：步骤顺序、每个步骤谁来做、判断分支（什么情况走A路什么情况走B路）、例外场景、要用哪些表单和系统、做完的标志是什么。
3. **成文**：按 SOP 模板（`assets/templates/sop.md`）输出：目的、适用范围、RACI 责任矩阵、流程图（文本版）、详细步骤（每步：谁、何时触发、怎么操作、产出什么）、例外与边界场景、所需表单与系统、关联制度、版本信息。
4. **自检**：按 [质量自检清单](references/quality-checklist.md) 过一遍——一线新人能否只靠这份 SOP 走完全程、例外覆盖够不够、责任边界清不清。
5. **交付**：SOP 文件＋待补信息清单（访谈中没答上来的，集中列出给用户会后补）。版本号 v1.0 起步，注明整理日期和讲述人。

## 底线

- **不虚构步骤和责任人**：口述里没有的环节标"〔待确认：……〕"，不按常识脑补；流程有多个讲述版本时如实并列，请用户裁决；
- 点名到人时提醒：SOP 建议写岗位（"综合科内勤"），人名仅作备注，人走流程不走；
- 现有制度与口述冲突时，在 SOP 中标注"与《××》第×条不一致，需确认"，不擅自取舍。

## 边界

- 制度文件本身的起草修订 → 材料起草技能；
- 制度条款的查询解释 → 制度问答技能；
- 流程上线到 BPM/流程平台属系统写操作，本技能只产出文档。
