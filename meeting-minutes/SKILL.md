# 会议纪要督办

把"开完会"变成"办了事"。上游 action tracking 的纪律：**每条行动项必须具体、有唯一责任人、有明确截止日期**——"尽快""相关科室"不是落实。纪律反过来也是红线：纪要里没有的，宁可标"待确认"，不能编。

## 流程

1. **拿到底稿**：用户给的录音转写文字、笔记、议程、参会名单。只有录音没有文字时，请用户先用宿主的转写能力出文字稿。
2. **通读并理结构**：分清三类内容——**决议**（会议定下来的）、**行动项**（谁在什么时间前做什么）、**讨论记录**（有分歧没结论的）。拿不准是决议还是个人意见的，标注待核实而不是当决议写。
3. **起草纪要**：按 [纪要格式规范](references/minutes-format.md)——标题、会议要素、出席列席、议题与讨论要点、决议事项、行动项、落款。
4. **提取行动项**：按 [行动项提取规则](references/actions.md) 逐条过——事项具体可验收、唯一责任人、明确日期、注明依赖与类型；缺责任人或缺日期的写"待确认"，不猜。拿不准的说法（"尽快办"）如实保留在讨论记录里，不硬转成行动项。
5. **生成督办台账**：把行动项整理为 JSON 后运行脚本：
   ```bash
   python "<SKILL>/scripts/actions.py" build --from 行动项.json --out 督办台账.csv --meeting "××办公会" --date 2026-09-10
   ```
   脚本会标出所有"待确认"项；**台账里不允许出现编造的责任人或日期**（脚本不生成默认值）。
6. **交付三件套**：纪要草稿＋领导速览（半页：定了什么、谁在何时交什么）＋督办台账 CSV。提醒用户：待确认项核实后再分发。

## 跟踪节奏（来自上游实践，写入交付提醒）

- 高优先级行动项：每天盯到办结；中优先：周例会核；低优先：下次同主题会议核；
- 逾期未办结：提示向责任人和其分管领导催办，并在下次相关会议议程中列出；
- 复查已有台账：
  ```bash
  python "<SKILL>/scripts/actions.py" check 督办台账.csv --asof 2026-09-13
  ```
  输出缺责任人/日期、日期非法、逾期未办结清单。

## 底线

- 决议、责任人、日期不虚构：这是纪要技能与造谣的唯一距离；
- 有争议的表述（谁说的、原话是什么）以录音/笔记为准，拿不准就写"会议讨论了××事项"这一层；
- 纪要涉及未公开人事、纪检内容时提醒用户按密级管理。

## 边界

- 会前准备 → 会前材料技能；
- 录音 → 文字的转写本身需要宿主能力，本技能从文字稿开始；
- 台账写入任务系统/OA 属写操作，默认不执行，需用户确认后手工或经审批通道进行。
