# 台账体检清单

脚本管"格式和逻辑"，本清单管"业务上对不对"。来自上游 explore-data 质量评估框架的机关人事改造。逐项过，发现项并入质量报告。

## 主键与粒度

- [ ] 一行＝一个自然人？有无一人多行（编制、聘用两条记录）导致的重复；
- [ ] 唯一键选哪个：身份证号最稳，工号可能跨系统不一致；
- [ ] 关键列（姓名＋身份证）同音同字的近似重复（张小明/张晓铭）。

## 字段口径

- [ ] "入职日期"是报到日、起薪日还是转正日——同一列混用两种口径是高发问题；
- [ ] "部门"是编制所在部门还是实际工作部门；
- [ ] 人员状态枚举（在编/聘用/借调/退休/离职）的标准值清单，谁维护；
- [ ] "离职日期"为空是"在职"还是"没填"——空值语义要区分。

## 与字典的映射

- [ ] 部门名称与组织机构字典逐一对照（"办公室"vs"委办公室"vs"XX委办公室"）；
- [ ] 学历、职称、政治面貌等枚举字段的取值是否落在标准集合内；
- [ ] 系统导入模板的字段名与本表表头的映射关系是否明确。

## 逻辑交叉

- [ ] 年龄、出生日期、身份证出生段三者自洽（脚本已查，注意基准日）；
- [ ] 入职日期晚于出生日期满16岁；退休年龄与出生日期、身份（女干部55/女工人50）的提示；
- [ ] 状态"退休"但有"离职日期"，状态"在职"但年龄超退休线——业务规则类提示。

## 上报格式

- [ ] 目标系统的模板要求：字段顺序、日期格式、编码（GB18030？UTF-8？）；
- [ ] 必填列与模板一致；多余列是否允许；
- [ ] 文件命名与报送要求（是否需要加密、是否脱敏）。

## 完整性分级（沿用上游框架）

| 级别 | 非空率 | 含义 |
| --- | --- | --- |
| 绿 | >99% | 完整 |
| 黄 | 95-99% | 查空值原因 |
| 橙 | 80-95% | 确认是否影响导入 |
| 红 | <80% | 基本不可用，先补数据 |
