# 台账数据体检

数据进系统之前拦住脏数据，比导入后再清洗便宜十倍。上游 explore-data 的经验是先画像后判断：先搞清楚每张表"一行代表什么、哪些列是主键"，再谈质量。

## 体检流程

1. **确认表的粒度与用途**：一行是一个人还是一条记录？导入哪个系统？上报给谁？不同目标对必填项和格式的要求不同——拿不到标准就按通用花名册检查。
2. **机械体检**（脚本，覆盖每个字段）：
   ```bash
   python "<SKILL>/scripts/ledger.py" check 花名册.xlsx --key 身份证号 --key 工号 --required 姓名 --required 身份证号 --asof 2026-09-13
   ```
   检查项：身份证校验码（GB 11643）及出生段有效性、身份证出生段与出生日期列交叉、身份证性别位与性别列交叉、年龄列与出生日期推算、唯一键重复、必填缺失、同列日期格式混用、未来日期、枚举值漂移（同一取值的多种写法）、占位值（N/A、未知、TBD）、字段完整性分级。表头不在第一行用 `--header`。
3. **语义复核**：按 [台账体检清单](references/ledger-checklist.md) 补足脚本查不了的——部门名称与组织机构字典的映射、字段口径（"入职日期"是报到日还是起薪日）、跨表同名人。
4. **出质量报告**：红色（导入前必须处理）＋黄色（建议核对）＋字段完整性分级＋逐项修复建议。位置写行号和列名，能直接定位到单元格。
5. **可选清洗**：用户明确要求时生成清洗副本（去首尾空格、日期规范化），**原文件永不改动**：
   ```bash
   python "<SKILL>/scripts/ledger.py" clean 花名册.xlsx 花名册_clean.csv
   ```

## 底线

- 身份证号等敏感字段在报告只引用行号和列名，完整证件号不整串出现在报告里（打码显示）；
- 红黄分级不混淆：校验码不符是红（确定性错误），性别推算不一致是黄（可能录入错也可能身份证错）；
- 修复建议给"怎么改"，不改原文件；清洗副本是新建文件且需用户明示。

## 边界

- 报表数字勾稽（合计、比率）→ 报表复核技能；
- 在册人员结构统计、人事月报 → 人力资源统计技能；
- 导入映射规则、组织机构字典的维护 → 属信息化职能，本技能只提示不一致。
