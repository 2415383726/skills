# 答案格式规范

沿用上游 policy-lookup 的答案骨架（Quick Answer / Details / Exceptions / Contact / Source），字段按机关制度场景改造。所有实质性回答使用此格式。

## 格式

```markdown
## 制度解答：[问题主题]

**结论**
[1-2 句直接回答：可以/不可以/怎么办/标准是多少。]

**依据**
- 《[文件名]》（[文号]，[生效/施行日期]）第 X 条："[条文关键原文引用]"
- [第二份依据，如有；或写"依据同上，第 Y 条"]

**具体说明**
[用大白话解释条文怎么适用到用户的情形：条件、流程、材料、时限。]

**例外与特殊情形**
- [条文中的除外情形、需额外审批的情形；没有则写"所查文件未载明例外情形"。]

**咨询渠道**
[条文解释权部门/科室；个案走什么程序。]

**来源**
[检索方式与位置：制度库《文件名》第 X 条；或用户提供的文件；或知识库路径。]
```

## 字段规则

- **结论**：一句话能说清就一句话。用户要办的事直接给"能办/不能办/这样办"。
- **依据**：条文引用允许摘录关键句，但不得改写原意；引用部分用引号标出。查到的文件没有文号时写"（无文号，发布日期 ××××）"，不编文号。
- **具体说明**：解释可以口语化，但不得超出条文范围做扩展承诺。
- **例外**：很多问题答案取决于例外条款，漏了例外等于答错。
- **来源**：写清"这条信息从哪来"，让下一个经办人能复核。

## 拒答与降级话术

| 情形 | 话术 |
| --- | --- |
| 制度库中未检索到 | "未检索到明确规定。建议咨询××部门确认，以其答复为准。" |
| 只有相关但不直接对应的条款 | 给出最接近条款并明说"未见直接规定，以下条款供参考"。 |
| 新旧版本并存 | "该事项现行为《新版文件》（文号），《旧版文件》已废止/被修订，请勿按旧文办理。" |
| 敏感个案 | "个案认定需由××部门按程序办理，此处仅提供制度一般规定：……" |

## 质量 self-check

- 每条实质性结论都有对应依据行吗；
- 条文引用与原文一致吗（没有改写、断章取义）；
- 检索关键词覆盖了同义说法吗（"探亲假/探望父母"）；
- 用户情形里的特殊点（异地、借调、编外）有没有被例外条款覆盖。
