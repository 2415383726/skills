# 变化判类与语义对齐

脚本的文本比较解决不了"变了算什么"。本文件定义两件事：条款怎么对齐算可靠，变化怎么分类算一致。

## 语义对齐规则

- 条号相同 → 同一条款，交给文本比较；
- 条号不同 → 先看正文是否相同（脚本已标"编号调整"），再看正文相似度：主题句一致（如都在讲"考核周期"）视为同一事项的修订；正文主题都不同的，按新增＋删除处理，不硬配；
- 拆分与合并：旧版一条拆成新版两条（或反之）是常见修订手法。判据：新版多条的正文合并后与旧版一条高度重合 → 标"拆分/合并"并注明新旧条号对应关系；
- 对齐拿不准的列进"待确认"，让用户裁决，不要默默猜。

## 变化类型定义

| 类型 | 判据 | 示例 |
| --- | --- | --- |
| 实质修改 | 权利、义务、标准、金额、比例变了 | 报销限额 800 元改 1000 元 |
| 口径变化 | 同一概念的定义或统计范围变了 | "在编人员"改为"在编及聘用人员" |
| 流程变化 | 办理环节、顺序、材料变了 | 由两级审批改为三级审批 |
| 责任变化 | 牵头部门、审批主体变了 | 由综合科改由财务科受理 |
| 时限变化 | 办理时限、生效日期、截止节点变了 | 报送时限由 5 个工作日改为 3 个 |
| 文字性修改 | 表述规范化，含义不变 | 错别字、标点、语序调整 |
| 编号调整 | 正文相同，条号移动 | 原第十二条变为第十五条 |

## 两个高危误判

1. **文字没变但含义变了**：条款写"按上级有关规定执行"，文字没动，但被引用的上级文件已换版。排查：unchanged 条款中所有指向外部文件的表达，列出清单提示用户核对外部文件是否修订。
2. **文字变了但意思没变**：为对齐上级新文风做的措辞调整。把它标成"实质修改"会造成宣贯噪音。排查：差异是否只发生在表述层（同义替换、语序、标点）。

## 判类输出要求

每条 modified/renumbered 记录给出一行判类结论：`第X条 → 类型：一句话说明变化点`。判类不确定的标"待确认"并写明拿不准的原因。
