# 制度新旧对比

制度修订后最贵的问题是"有人还在按旧文办"。本技能产出一份能直接用于宣贯的对比报告：改了什么、对谁有影响、办事的人要注意什么。

## 工作流程

1. **拿到两版文件**：明确哪版是旧、哪版是新（按发文日期或文号，用户说不清时先确认）。支持 md/txt/docx。
2. **机械对齐**：运行条款对齐脚本，得到文字相同/有差异/新增/删除/编号调整的统计和逐条对照：
   ```bash
   python "<SKILL>/scripts/clauses.py" align 旧办法.docx 新办法.docx --out 对齐报告.md
   ```
   脚本只做拆分和文本比较；无法识别"第X条"结构时，改用逐段对照并在报告中说明。
3. **语义判类**：对每条"文字有差异"的条款，按 [变化判类与语义对齐](references/diff-workflow.md) 归类——实质修改、文字性修改、口径变化、流程变化、责任变化、时限变化；特别警惕"文字没变但含义变了"（条款引用的外部文件已更新）和"文字变了但意思没变"（只调整表述）。
4. **影响解读**：按 [影响检查清单](references/impact-checklist.md) 找出需要跟着改的东西——配套表单、办事流程、FAQ、系统字段、台账栏目、宣贯材料。
5. **按格式出报告**：见 [对比报告格式](references/output-format.md)。

## 底线

- **语义判断必须基于对照表**：不确定两版条款是否同一事项时，向用户确认而不是硬配对；
- **不替文件下结论**："以正式发布的文本为准"，报告开头注明所用两版文件的名称与来源；
- 检索不到条款结构、文件损坏等脚本异常如实说明，不编造对齐结果。

## 边界

- 单版制度的解释与查询 → 制度问答技能；
- 修订说明、宣贯通知的起草 → 材料起草技能；
- 报告发现需修订配套制度时，只列清单，不代为修改其他制度。
